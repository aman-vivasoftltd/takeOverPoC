Finding summary

Affected host
staging-real-2.windsurf.com
Vulnerability class
Dangling DNS record → Subdomain Takeover (CWE-350)
Dangling record type
CNAME pointing to an unclaimed / de-provisioned Vercel deployment target
Impact
Arbitrary content hosting under the target's own subdomain; potential for phishing, cookie/session abuse against the parent domain's origin, and reputational damage
This page served from
A Vercel project claimed by the researcher at the exact hostname above
Reported by
Aman Bhuiyan — Independent Security Researcher, Bangladesh
Date observed
15 September 2026

How this was demonstrated

  1. DNS lookup showed staging-real-2.windsurf.com resolving via CNAME to a Vercel deployment hostname that returned Vercel's "Deployment not found" / unclaimed-project response.
  2. The researcher registered a new project on Vercel and added the exact idle hostname as a custom domain — Vercel accepted the assignment because no existing project on the platform had claimed it.
  3. Vercel issued the domain verification and began serving traffic for staging-real-2.windsurf.com from the researcher's project, confirming full control over the content returned at that hostname.
  4. This page is the content now served at that hostname, serving solely as evidence for the report below. No data was accessed, modified, or exfiltrated, and no destination other than this notice was configured.

Suggested remediation

  1. Remove the dangling CNAME record for staging-real-2.windsurf.com from the DNS zone, or
  2. Re-provision and re-claim the corresponding Vercel project/domain under the organization's own Vercel account before the record is restored.
  3. Audit other subdomains for similarly stale CNAME records pointing to decommissioned third-party services (Vercel, Netlify, Heroku, GitHub Pages, S3, etc.).
